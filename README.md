# Контекст-бот для MAX

Реализация ТЗ проекта: общий пользовательский пул токенов, подписки, YooKassa, промокоды, иерархия `user/admin/creator`, контекст групповых чатов, cooldown и устойчивое состояние после перезапуска.

## Роли

- `user` — обычный пользователь.
- `admin` — административная панель, бесконечный доступ к LLM, создание промокодов на токены/подписки/admin.
- `creator` — все права admin + промокоды creator, список creators, снятие admin и самостоятельный выход из роли.

Все административные действия повторно проверяются на backend. Creator не может снять creator; admin не может управлять admin/creator.

## Токены

Токены принадлежат пользователю, а не чату. Хранение выполняется в `token_grants`; `chat_id` в этой таблице отсутствует.

Порядок расходования: `subscription` → `promo` → `trial` → `purchased`.

Trial: 30 токенов один раз на пользователя. Покупка: 10 токенов за 300 ₽.

## Подписки

- 1 месяц — 99 ₽ / 30 токенов;
- 3 месяца — 259 ₽ / 90 токенов;
- 6 месяцев — 559 ₽ / 180 токенов.

Во время обычной активной подписки LLM бесплатен. Подписочные токены имеют срок до окончания соответствующей подписки и после него не используются. `admin`/`creator` имеют role-based бесконечный доступ и не зависят от таблицы платных подписок.

## Промокоды

Поддерживаются токены, подписки, вечная подписка, `admin` и `creator`; режимы `once`, `limited`, `unlimited`. История использования хранится отдельно. Первый административный промокод создаётся один раз при инициализации БД и выводится в лог только в момент создания.

## Cooldown

LLM cooldown хранится отдельно для каждого `chat_id` и по умолчанию равен 10 минутам. Он запускается только после успешного LLM-запроса и переживает перезапуск.

## Контекст и сегментация

Бот сохраняет текстовые сообщения и опросы из групповых чатов. В меню сводки можно выбрать одного или нескольких участников, после чего в LLM передаётся только их контекст за выбранный период.

Удаление и редактирование сообщений синхронизируются с локальной БД через события MAX `message_removed` и `message_edited`, поэтому удалённые сообщения не должны оставаться в будущих сводках.

## YooKassa

Оплата подтверждается через `payment.succeeded` webhook. Дополнительно в заказе есть кнопка «Проверить оплату»: бот сам запрашивает текущий статус платежа у YooKassa, поэтому начисление не зависит только от доставки webhook. Проверяются payment ID, order ID, сумма, валюта, статус и товар. Fulfillment транзакционный и идемпотентный.

## Миграция

Старая таблица `user_chat_balances` автоматически переносится в `token_grants`. Trial и остатки сохраняются, а старая таблица переименовывается в `user_chat_balances_legacy` и больше не участвует в работе приложения.

## Запуск

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python main.py
```

Production использует Python 3.13. Каталог `data/` должен сохраняться между перезапусками, потому что там находится SQLite-база.

В личном чате нативная кнопка MAX «Начать» обрабатывается тем же сценарием, что и `/start`. В группах этот обработчик не меняет существующее поведение.
